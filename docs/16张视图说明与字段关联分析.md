本文整理 Data Agent 当前 Knowledge Base 中的 16 张 ERP 业务视图，并结合《16 张视图解释.xlsx》中的实际使用场景，对每张视图的用途、数据粒度和字段含义进行说明。字段关联结论使用 `data-agent-2026-7-24.sqlite` 中的实际数据进行验证。

字段关联比较采用以下规则：

- 比较非空字段值时，先去除首尾空格，并忽略英文字母大小写。
- “取值覆盖率”是两个字段去重值集合的交集占各自集合的比例。
- 对可能来自同一明细记录的视图，除比较单字段外，还比较多个公共字段组成的去重记录。
- 取值相同只能证明数据域或当前快照中的数据一致；最终是否能直接连接，还必须结合字段的业务含义和视图粒度。
- Knowledge Base 的 `database_profile.json` 仍记录 2026-07-15 数据文件，因此本文的行数、空值情况和字段关联统计以用户指定的 2026-07-24 SQLite 文件为准；视图用途和字段语义沿用 Knowledge Base 中已审核的目录。

## 3. 各视图说明和字段含义

### 3.1 `AiQueryPartV`：物料基础视图

该视图是物料主数据入口，用于根据物料编码或描述确认物料是否已经建档，并查询物料的基础名称信息。Excel 中工程服务中心、研发中心和市场部都使用它进行物料编码查询、物料名称规格检查和物料存在性确认。每一行表示某公司下的一项物料。

- `Company`: 物料所属公司的代码。
- `CompanyName`: 物料所属公司的名称。
- `PartNum`: 物料编码，也可理解为料号或图号。
- `PartDescription`: 物料名称、规格或描述。

### 3.2 `AiQueryPartOnHandV`：物料库存视图

该视图用于查询物料当前库存数量以及库存所在的库位或货位。Excel 中市场部用它判断是否有库存可以发货，工程服务中心和研发中心用它查询物料库存及库位。每一行表示一个物料在一个库位中的库存记录，因此同一物料可能出现多行。

- `Company`: 库存所属公司的代码。
- `CompanyName`: 库存所属公司的名称。
- `PartNum`: 库存物料编码。
- `PartDescription`: 库存物料的名称或规格描述。
- `BinNum`: 库位或货位编码。
- `BinName`: 库位或货位名称。
- `Qty`: 该物料在该库位中的现有数量。

### 3.3 `AiQueryBomV`：BOM 结构视图

该视图用于反向查询某个子物料被哪些上级部件使用，也可以查看上级部件与子物料之间的 BOM 关系。Excel 中研发中心用它查询物料用于哪个部件。每一行表示一组上级部件与子物料的对应关系。

- `Company`: BOM 所属公司的代码。
- `CompanyName`: BOM 所属公司的名称。
- `Plant`: BOM 所属的工厂或生产地点。
- `PartNum`: 上级部件或母件的物料编码。
- `PartDescription`: 上级部件或母件的名称及规格描述。
- `ECOMtl_MtlPartNum`: BOM 中的子物料编码。
- `MtlPartDescription`: BOM 中子物料的名称及规格描述。

### 3.4 `AiQueryPoPriceV`：采购价格视图

该视图用于按物料查询采购价格相关信息，包括最新采购价、最新供应商、最新采购订单、采购提前期和平均采购价。Excel 中市场部在报价时用它估算零件成本。每一行代表一个物料的采购价格摘要信息。

- `Company`: 采购业务所属公司的代码。
- `CompanyName`: 采购业务所属公司的名称。
- `PartNum`: 采购物料编码。
- `LineDesc`: 采购订单物料行的描述。
- `IUM`: 物料的库存计量单位。
- `Plant`: 采购物料所属的工厂或地点。
- `LeadTime`: 采购提前期，表示从采购到预计可获得物料所需的时间。
- `NewPrice`: 该物料的最新采购价格。
- `NewVendorName`: 最新一笔采购记录对应的供应商名称。
- `NewPONum`: 最新一笔采购记录对应的采购订单号。
- `AvgPrice`: 该物料的平均采购价格。**当前 2026-07-24 SQLite 快照中此字段 58,784 行全部为空**；快照元数据说明，源 SQL Server 计算列查询超时，因此离线导入时保留字段但没有导入数值。

### 3.5 `AiQueryPoProgressV`：采购到货进度视图

该视图用于查看采购订单物料的下单时间、需求时间、收货数量、在检数量及净收货数量。Excel 中工程服务中心用它查询物料预计到货时间和实际到货信息。每一行表示一条采购订单物料行。

- `Company`: 采购订单所属公司的代码。
- `CompanyName`: 采购订单所属公司的名称。
- `PONum`: 公司内部采购订单号。
- `VendorID`: 供应商业务代码。
- `VendorName`: 供应商名称。
- `OrderDate`: 采购订单创建或下单日期。
- `PartNum`: 采购物料编码。
- `LineDesc`: 采购订单物料行描述。
- `OrderQty`: 采购订单行的订购数量。
- `DueDate`: 采购订单行的需求或到期日期。
- `ReceivedQty`: 已收货数量。
- `InspectionQty`: 已到货但仍处于检验状态的数量。
- `NetReceivedQty`: 扣除相关调整后计入的净收货数量。

### 3.6 `AiQueryPoOverViewV`：采购追踪视图

该视图用于采购订单全过程追踪，覆盖审批状态、订单数量、收货数量、开票数量和剩余数量。Excel 中采购部将它用于“采购追踪一览表”和“订单进度查询”。每一行表示一条采购订单物料行。

- `Company`: 采购订单所属公司的代码。
- `CompanyName`: 采购订单所属公司的名称。
- `PONum`: 公司内部采购订单号。
- `VendorID`: 供应商业务代码。
- `Vendor_Name`: 供应商名称；与其他采购视图中的 `VendorName` 命名不同。
- `OrderDate`: 采购订单创建或下单日期。
- `PartNum`: 采购物料编码。
- `LineDesc`: 采购订单物料行描述。
- `OrderQty`: 采购订单行的订购数量。
- `DueDate`: 采购订单行的需求或到期日期。
- `ReceivedQty`: 已收货数量。
- `InvoiceQty`: 该采购订单行已经取得或匹配的供应商发票数量。
- `RemainQty`: 采购订单行尚未完成的剩余数量。
- `ApproveStatus_c`: 采购订单的审批状态。

### 3.7 `AiQueryJobV`：项目工单视图

该视图用于根据项目号查询项目下已经建立的工单及其要求交期。Excel 中生产管理部用它支持新项目工单输入，并核对项目下的工单数量和交期。每一行表示项目下的一张工单。

- `Company`: 工单所属公司的代码。
- `CompanyName`: 工单所属公司的名称。
- `ProjectID`: 工单关联的项目号。
- `JobNum`: 工单号。
- `ReqDueDate`: 工单的要求完成日期或要求交期。

### 3.8 `AiQueryJobProgressV`：工单完工进度视图

该视图用于查询工单计划数量、累计报工数量和末道工序完成数量。Excel 中机械仓库用它查询工单完工和入库前的执行进度。每一行表示一张工单的进度记录。

- `Company`: 工单所属公司的代码。
- `CompanyName`: 工单所属公司的名称。
- `JobNum`: 工单号。
- `PartNum`: 工单生产的物料编码。

该视图用于生产管理中的工单执行追踪，提供工单、生产物料、计划数量和末道工序完成数量。Excel 中生产管理部用它管理和查询当前工单执行情况。每一行表示一张进入该追踪范围的工单；当前快照中的记录范围小于完整工单进度视图。

- `PartNum`: 工单生产的物料编码。

### 3.10 `AiQueryPartTimeTrackingV`：物料时间轴视图

该视图把物料在不同日期发生的收货、需求和余额变化按来源事件整理成时间轴。Excel 中生产管理部用它查询零件在一段时间内的供需变化。每一行表示某物料在某个日期和来源下的一项时间轴事件。

- `Company`: 物料事件所属公司的代码。
- `CompanyName`: 物料事件所属公司的名称。

## 4. 字段关联分析

### 4.1 可以确认属于同一业务字段或同一数据域的字段

#### 公司代码和公司名称

- 16 张视图中的 `Company` 都表示公司代码。当前数据主要使用 `C001` 和 `C002`，可作为跨视图连接条件之一。
- `CompanyName` 与 `ComName` 都表示公司名称。拥有两家公司数据的视图中，两个去重名称集合完全一致；只包含一家公司的视图，其名称集合是该全集的子集。
- `Company` 与 `CompanyName`/`ComName` 不是同一个字段：前者是代码，后者是名称，但当前数据中存在稳定的代码到名称映射。
- 跨公司连接业务对象时，应优先使用 `Company` 加业务编号，不能只用物料号、项目号或工单号。

#### 物料编码和物料描述

- 多数视图中的 `PartNum` 属于同一个“物料编码”数据域，可与 `AiQueryPartV.PartNum` 对照。库存视图的 12,166 个去重物料号全部出现在物料基础视图中；BOM 子物料字段 `ECOMtl_MtlPartNum` 的 26,788 个去重值也全部出现在物料基础视图中。
- `AiQueryBomV.ECOMtl_MtlPartNum` 与其他视图的 `PartNum` 都是物料编码，但在 BOM 中承担“子物料”角色；`AiQueryBomV.PartNum` 则承担“上级部件”角色。因此二者数据域相同，业务角色不同。
- `AiQueryProjectJobV.JobHead_PartNum` 是工单头上的生产物料编码，和 `PartNum` 属于同一类字段，但当前 6,957 个去重值中只有 3,722 个出现在物料基础快照里。它可以用于物料关联，但不能假设每个工单物料都一定能在当前 `AiQueryPartV` 快照中匹配。
- 销售订单的 3,444 个去重 `PartNum` 中有 3,443 个能在物料基础视图中匹配，覆盖率为 99.97%。
- 采购进度视图的 49,559 个去重 `PartNum` 中有 43,991 个能在物料基础视图中匹配，覆盖率为 88.76%。无法匹配的值可能涉及历史、临时、非标准或已停用物料，需要逐项核查，不能直接判为脏数据。
- `PartDescription`、`MtlPartDescription` 和 `JobHead_PartDescription` 都是与相应物料编码配套的描述字段。以物料号为键比较时：
  - 物料基础视图与库存视图有 12,166 个共同物料号，每个共同物料号至少存在一个相同描述，98.23% 的物料号拥有完全相同的描述集合。
  - 物料基础视图与 BOM 子物料有 26,788 个共同物料号，每个共同物料号至少存在一个相同描述，98.66% 的描述集合完全一致。
  - 物料基础视图与项目工单视图有 3,722 个共同工单物料号，92.50% 至少有一个相同描述。
- 描述字段不适合单独作为连接键，因为名称可能重复、修改或包含不同版本的规格文本。应使用 `Company + 物料编码` 连接，再把描述用于展示或一致性检查。

#### 工单字段

- `AiQueryJobV.JobNum`、`AiQueryJobProgressV.JobNum`、`AiQueryJobTrackingV.JobNum` 和 `AiQueryProjectJobV.JobHead_JobNum` 都表示工单号。
- `AiQueryJobV` 与 `AiQueryJobProgressV` 的去重工单号集合完全相同，均为 29,466 个。
- `AiQueryJobTrackingV` 的 356 个工单号全部包含在上述完整工单集合中，说明生产追踪视图是当前工单范围的子集。
- `AiQueryProjectJobV.JobHead_JobNum` 的 8,902 个去重工单号全部包含在 `AiQueryJobV.JobNum` 和 `AiQueryJobProgressV.JobNum` 中。
- 对 `AiQueryJobProgressV` 和 `AiQueryJobTrackingV` 同时比较 `Company`、公司名称、`JobNum`、`PartNum`、物料描述、`JobQty` 和 `JobOprCompQty` 后，生产追踪视图中的 356 个去重组合全部能在工单进度视图中找到。可以确认这两张视图的这些公共字段来自同一批工单事实，只是筛选范围不同。

#### 项目字段

- `AiQueryJobV.ProjectID`、`AiQueryProjectV.ProjectID`、`AiQueryProjectJobV.ProjectID` 和 `AiQueryProjRevCstV.ProjectID` 都表示项目号。
- `AiQueryProjectV` 与 `AiQueryProjRevCstV` 都有 731 个非空去重项目号，两个集合完全一致。
- `AiQueryJobV` 与 `AiQueryProjectJobV` 都有 530 个非空去重项目号，两个集合完全一致，并且全部包含在项目概览和项目财务视图的 731 个项目号中。
- `ProjectDesc` 与 `Project_Description` 都表示项目描述。项目概览与项目财务视图的 810 个去重描述完全一致；项目工单视图的 561 个描述全部包含在其中。
- 按项目号比较描述时，`AiQueryProjectV` 与 `AiQueryProjRevCstV` 的 731 个共同项目号描述完全一致；`AiQueryProjectJobV` 的 530 个共同项目号中，每个项目至少存在一个相同描述，95.09% 的项目拥有完全相同的描述集合。

#### 采购订单、供应商和采购明细字段

- `AiQueryPoProgressV.PONum` 与 `AiQueryPoOverViewV.PONum` 都是公司内部采购订单号。两张视图均有 27,697 个去重采购订单号，取值集合完全一致。
- `AiQueryPoPriceV.NewPONum` 也是采购订单号，但只表示物料最新采购记录对应的订单。它的 14,012 个去重值全部包含在上述采购订单号集合中，因此是同一数据域中的“最新订单号子集”。
- `AiQueryPoProgressV.VendorID`、`AiQueryPoOverViewV.VendorID` 和 `AiQueryPayablesV.VendorID` 都表示供应商业务代码。两个采购进度视图的 791 个去重值完全一致；其中 652 个能在应付视图中匹配。
- `VendorName`、`Vendor_Name` 与 `NewVendorName` 都属于供应商名称字段。`AiQueryPoProgressV.VendorName` 与 `AiQueryPoOverViewV.Vendor_Name` 的 803 个去重值完全一致；`NewVendorName` 的 761 个去重值全部包含在这两个集合中。
- 以 `VendorID` 为键比较采购进度与采购追踪视图，791 个共同供应商的名称集合 100% 一致。
- 对采购进度与采购追踪视图同时比较 `Company`、公司名称、`PONum`、`VendorID`、`OrderDate`、`PartNum`、`LineDesc`、`OrderQty`、`DueDate` 和 `ReceivedQty` 后，两张视图都得到 160,931 个去重组合，且组合完全一致。可以确认这些公共字段来自相同的采购订单行事实；两张视图的差别主要在额外指标：
  - `AiQueryPoProgressV` 增加 `InspectionQty` 和 `NetReceivedQty`，侧重到货与检验。
  - `AiQueryPoOverViewV` 增加 `InvoiceQty`、`RemainQty` 和 `ApproveStatus_c`，侧重审批、开票和剩余数量。

#### 客户名称和币种

- `AiQueryProjectV.CustName` 与 `AiQueryProjRevCstV.CustDesc` 都是项目客户名称，两个字段的 103 个去重值完全一致。
- `AiQueryReceivablesV.CustName` 和 `AiQuerySoOverViewV.Customer_Name` 也属于客户名称数据域。销售订单中的 121 个客户名称有 107 个出现在应收视图中，覆盖率为 88.43%；应收视图中的 142 个客户名称有 107 个出现在销售订单视图中。
- 客户名称虽然可以辅助核对，但不宜作为稳定主键。应收视图应优先使用 `CustID`；销售订单和项目视图当前没有提供客户代码，跨视图连接客户时需要名称标准化或补充客户代码字段。
- `AiQueryPayablesV.CurrCode`、`AiQueryReceivablesV.CueeCode` 和 `AiQuerySoOverViewV.CurrencyCode` 都表示币种代码。应收与销售订单各有 3 个去重币种且完全一致；应付视图中的 2 个币种全部包含在这 3 个币种中。

### 4.2 取值相关，但不能当作同一个字段直接替换

#### 物料描述与订单行描述

`PartDescription`、`MtlPartDescription` 和 `JobHead_PartDescription` 是物料主数据或工单物料描述；`LineDesc` 是采购或销售订单行上保存的描述。订单行描述可能复制自物料描述，也可能被人工修改、保留历史文字或用于非标准物料。

实际数据支持这种区别：

- 采购价格、采购进度和采购追踪中的 `LineDesc` 高度相关。采购价格视图的 45,663 个去重描述全部出现在两个采购进度视图中；采购进度与采购追踪的 52,131 个去重 `LineDesc` 完全一致。
- 物料基础视图有 71,651 个去重 `PartDescription`，采购进度的 52,131 个去重 `LineDesc` 中只有 26,402 个与之完全相同，覆盖率为 50.65%。
- 销售订单的 3,554 个去重 `LineDesc` 中有 2,831 个与物料基础描述相同，覆盖率为 79.66%。

因此，订单行描述与物料描述是“内容可能相同的不同业务字段”，不应直接按描述连接。正确方式是先按 `Company + PartNum` 关联，再比较描述。

#### 数量字段

以下数量字段彼此有关，但描述的是不同业务阶段，不能因为数值偶尔相同就当作同一个字段：

- 生产：`JobQty`/`JobHead_ProdQty` 是计划生产数量，`LaborQty` 是报工数量，`JobOprCompQty` 是末道工序完成数量，`CompleteQty` 是完工入库数量。
- 采购：`OrderQty` 是采购订购数量，`ReceivedQty` 是收货数量，`InspectionQty` 是在检数量，`NetReceivedQty` 是净收货数量，`InvoiceQty` 是采购开票数量，`RemainQty` 是剩余数量。
- 销售：`OrderQty` 是销售订购数量，`ShipQty` 是发货数量，`ReturnQty` 是退货数量，`InvoiceQty` 是销售开票数量，`RedQty` 是红字或冲销数量。
- 库存与物料时间轴：`Qty` 是当前库位库存，`ReceiptQty` 是事件收货量，`RequiredQty` 是事件需求量，`BalanceQty` 是事件后的结余。

特别需要注意：采购视图和销售视图都存在 `OrderQty` 与 `InvoiceQty`，字段名相同但分别属于采购订单和销售订单，不能跨业务模块合并为同一事实。

#### 日期字段

以下字段都是日期，但业务事件不同：

- `OrderDate`: 订单创建或下单日期；采购和销售模块中分别对应各自订单。
- `DueDate`: 采购需求/到期日期，或物料时间轴事件日期。
- `ReqDueDate`: 生产工单要求完成日期。
- `NeedByDate`: 客户或销售订单要求交付日期。
- `Dlvdate`: 项目实际或计划发货日期。
- `Checkdate`: 项目验收日期。

日期值相同只说明业务计划可能衔接，不能证明字段相同。做交期分析时，应明确比较的是采购到料、工单完工、销售交付还是项目验收。

### 4.3 同名但明确不是同一业务字段的字段

- `AiQuerySoOverViewV.PONum` 与采购视图中的 `PONum`：销售视图中是客户采购订单号或客户参考号；采购视图中是公司内部向供应商下达的采购订单号。
- `AiQueryPayablesV.Amount` 与 `AiQueryReceivablesV.Amount`：一个是应付金额，一个是应收金额；金额口径结构相似，但业务方向相反。
- `AiQueryPayablesV.RemainAmount` 与 `AiQueryReceivablesV.RemainAmount`：一个是未付余额，一个是未收余额。
- 应付和应收视图中的 `BeqAmount`、`BeqRemainAmount`：都表示本币折算口径，但分别属于供应商应付和客户应收。
- 采购 `OrderDate` 与销售 `OrderDate`：名称相同，分别属于采购订单和销售订单。
- 采购 `OrderQty`/`InvoiceQty` 与销售 `OrderQty`/`InvoiceQty`：名称相同，但订单类型和业务方向不同。

## 5. 关联使用时的限制与建议

1. **所有关联优先带上 `Company`。** 当前快照包含两家公司，同一个业务编号可能在不同公司重复。
2. **不要只按描述或名称连接。** 物料描述、供应商名称和客户名称可能发生修改、重名或格式差异，应优先使用代码。
3. **注意视图粒度。** 项目、工单、订单行、库存库位和时间轴事件的粒度不同，直接连接可能放大行数；聚合前应先确定目标粒度。
4. **采购订单行缺少明确行号。** `PONum + PartNum` 不一定唯一；如果源 SQL Server 视图能够补充采购订单行号，建议将其加入 Knowledge Base 和离线快照。
5. **客户关联缺少统一客户代码。** 项目和销售订单视图只提供客户名称，而应收视图提供 `CustID`。建议后续在项目和销售视图中补充客户代码。
6. **`AvgPrice` 当前不可用于 SQLite 测试。** 若需要平均采购价，应修复 SQL Server 计算列超时问题，或采用经过业务确认的替代计算方法，不能把空值当成 0。
7. **离线结果只反映 2026-07-24 快照。** 本文确认的包含关系和覆盖率可能随 SQL Server 实时数据变化；部署到公司服务器后，如切换到实时 SQL Server，应重新执行字段关联检查。
