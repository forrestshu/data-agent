# Data Agent 自然语言查询测试清单

以下问题可直接输入 Data Agent 查询框，用于验证精确查询、包含匹配、聚合关系查询和多轮模糊澄清能力。查询结果以当前 SQLite 数据快照为准。

> 测试口径：“螺栓之类”“名称包含威图”属于文本包含匹配，系统应直接查询，不应触发前端追问。本文档中的“模糊查询”特指业务对象、指标、范围或判定标准不足，首轮必须返回 `clarification_required` 的查询。

## 五、二段模糊查询：补充后仍然追问

这组用例专门验证完整澄清历史和连续追问。第一次回复故意只补充一部分信息，预期前端继续显示澄清输入框，而不是直接返回答案。

### 案例 A：只补充订单类型

- 首轮输入：`帮我看看订单情况`
- 系统首次追问：想查采购订单还是销售订单？
- 故意仍然模糊的回复：`采购订单`
- 实测第二次追问：想查采购订单的进度、收货、审批、采购价还是剩余数量？
- 可完成的第二次回复：`查看采购单 2040760 的订购数量、已收数量、在检数量和净收货数量`
- 最终实测状态：`completed`

### 案例 B：只补充查询指标

- 首轮输入：`查一下物料情况`
- 系统首次追问：想查哪些物料，以及库存、采购价还是其他信息？
- 故意仍然模糊的回复：`查库存`
- 实测第二次追问：查所有物料还是特定物料？按库位分别显示还是汇总？
- 可完成的第二次回复：`查询物料 110000012，汇总全部库位的库存`
- 最终实测状态：`completed`

### 案例 C：只补充进度阈值

- 首轮输入：`哪些工单进度落后`
- 系统首次追问：如何定义“进度落后”？
- 故意仍然模糊的回复：`完工入库数量低于生产数量的 80% 就算进度落后`
- 实测第二次追问：“完工入库数量”指末道工序完工数还是项目工单完工入库数？是否限定公司或项目？
- 可完成的第二次回复：`使用项目工单完工入库数量 CompleteQty，不限定公司或项目`
- 最终实测状态：`completed`

## 六、实测注意事项

- 大模型的追问文字可能有小幅变化；验收应以返回状态和是否要求补齐关键信息为准，不要只比较追问的逐字文案。
- “哪些物料快没库存了”首轮会同时询阈值和库位汇总方式。本次实测中，只回复“现有量低于 25”时，模型直接推断为汇总全部库位并返回了答案。因此这一条当前不适合用于验收“必须二次追问”。
- “最近采购价格变化比较大的物料”虽会追问判定标准，但当前语义层没有可靠的前次采购价对比信息，不宜列为“补充后必然可完成”的模糊查询。
