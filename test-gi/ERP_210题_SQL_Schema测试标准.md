# ERP 210 题 SQL Schema 测试标准

每道题依次评测视图、筛选条件、查询字段和其他关键字内容。四项全部通过，该题才判定为正确。

## 1. 视图

- 标准答案只有一个视图时，测试答案必须使用该视图。
- 标准答案列出多个可选视图时，测试答案匹配其中任意一个即可。
- 不能仅因其他视图含有同名字段就判定正确；只有标准答案明确列出的业务等价视图才可接受。
- 视图名称比较时忽略数据库前缀、方括号和字母大小写。

## 2. 筛选条件

- 标准答案中的核心筛选条件必须全部存在，字段、运算符和筛选值的业务含义必须一致。
- 忽略条件顺序、括号、空格、大小写及 `TRIM`、`LTRIM`、`RTRIM` 等不改变业务范围的写法差异。
- `IN` 与等价的多个 `OR`、交换等号两侧等语义相同的写法可以匹配。
- 对 `LineDesc`、`PartDescription`、`MtlPartDescription`、`JobHead_PartDescription` 等描述类字段，标准答案使用完整描述精确匹配时，测试答案使用 `LIKE '%完整描述%'` 也判定为正确。`LIKE` 中间必须完整保留标准筛选值；缺字、改词、拆分成更短关键词或增加内部通配符而扩大范围，仍判定为错误。
- 除上述描述类字段的完整包含例外外，测试答案缺少核心条件，或增加会扩大、缩小或改变查询范围的条件，均判定为错误。

## 3. 查询字段

- 标准答案要求的业务字段必须全部包含在测试答案的输出字段中，即标准字段集合必须是测试字段集合的子集。
- 测试答案可以额外返回用于说明结果的字段，但额外字段不能改变答案的业务含义或结果粒度。
- 对“总数、合计、还有多少”等单值汇总问题，测试答案应只输出回答所需的聚合结果。附加普通字段如果迫使查询增加 `GROUP BY`、把一个总量拆成多行，或形成没有确定业务含义的混合聚合，则查询字段判定为错误。
- 经《16张视图说明与字段关联分析.md》确认属于同一业务字段的别名可以匹配，例如 `JobNum` 与 `JobHead_JobNum`。
- 同名但业务含义不同的字段不能匹配，例如采购 `OrderQty` 与销售 `OrderQty`。
- 字段只出现在 `WHERE`、`JOIN` 或中间计算中，但没有形成最终输出答案时，不算查询字段匹配。

## 4. 其他关键字内容

- 只检查回答问题所必需的操作，包括聚合、去重、分组、排序、条件判断和数量限制。
- SQL 写法可以不同，但业务效果必须一致，例如 SQL Server 的 `TOP` 与 SQLite 的 `LIMIT`。
- 必需的 `SUM`、`COUNT`、`ORDER BY`、`CASE` 等操作缺失或使用错误，判定为错误。
- 标准答案要求 `DISTINCT` 而测试答案未使用时，该题仍判定为正确，但记为警告；警告说明结果在存在重复数据时可能返回重复记录。
- `GROUP BY` 等仅为配合输出字段而增加的语法可以接受，但不能改变标准答案要求的结果粒度。
- 标准答案为无分组的单值聚合时，测试答案默认不得增加顶层 `GROUP BY`。只有分组字段已被精确等值条件固定、且不会把一个答案拆成多个结果时，才可视为冗余但等价；`LIKE` 包含筛选不视为固定为唯一值。
- 多余操作如果不改变结果可以接受；如果改变返回数量、排序、分组、去重或计算结果，则判定为错误。
